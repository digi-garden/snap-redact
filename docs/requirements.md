# 要件定義書：Snap-Redact（MVP）確定版 v1.2

最終更新：2026-11-17 ／ 作成：ぎりぎりSE（digi-garden）

* v1.0（2026-11-15）：初版
* v1.1（2026-11-17）：最初から Public で開発する方針と、リポジトリの設定（ルールセット、push protection、CodeQL）を追加
* v1.2（2026-11-17）：外部レビューの指摘を反映（座標の外側丸め、window での drop 抑止、バッジ文言、Safari のコピー、画像サイズの上限、複数 MIME、未読み込み時の Ctrl+C、未保存時の差し替え確認、brand-assets の同梱、成功指標の主従）。モザイクの削除提案は不採用（文字以外を隠す用途で必要。文字には黒塗りを推奨する注意文で対応。`drawImage` による縮小・拡大方式のため性能面の懸念は小さく、実装時に計測する）。本版をもって要件を確定する

## 1. プロジェクト概要

| 項目 | 内容 |
| :--- | :--- |
| 製品名 | Snap-Redact（スナップリダクト） |
| シリーズ | CircleNote シリーズ第3弾（第1弾 Mask & Unmask、第2弾 Context-Packer） |
| サービスURL | `https://circle-note.com/snap-redact/` |
| リポジトリ | `digi-garden/snap-redact`（**最初のコミットから Public**） |
| コンセプト | Qiita / Zenn / Slack にスクショを貼る前の「5秒前処理」。画像を外部へ一切送らず、ブラウザ内だけで黒塗り・モザイクして、そのままクリップボードへ戻す |

### 1.1 ターゲットユーザー
* Qiita / Zenn / 技術ブログの執筆者（開発画面・ログ・管理コンソールのスクショから機密を隠したい）
* Slack / Teams で画面スクショを共有するエンジニア
* X で個人開発の進捗画面を投稿する個人開発者

### 1.2 プロジェクトの目標
* **公開実績とユーザーの反応を得ること**（収益化は目標にしない）
* 公開と同時に Qiita / Zenn へ記事を投稿する

## 2. 差別化（競合との違い）

同じ「ブラウザ内処理・アップロードなし・貼り付け対応」のツールはすでに多数ある。Windows 11 の Snipping Tool にも黒塗り機能が標準で入っている。そのため、次の2本を差別化の柱とする。

### 柱A：送信しないことを「確かめられる」
* CSP の `connect-src 'none'` などにより、外部通信を**仕組みとして不可能**にする（「送信しません」という宣言だけで終わらせない）
* リポジトリを Public にし、画像を扱うコードと `_headers` を誰でも読めるようにする
* 画面上と README / 記事に、DevTools で確認する手順（Network タブ・CSP 違反の表示）を載せる

### 柱B：コピーで完結する（5秒ワークフロー）
* `Ctrl+V` で貼る → ドラッグで隠す → `Ctrl+C` でコピー。ファイル保存もボタン操作も不要
* ボタン（「📋 画像をコピー」）でも同じ操作ができる

### 2.1 柱にしないもの（明記）
* OCR による自動検出（v2 以降で検討）
* 画像編集機能の豊富さ（注釈、矢印、トリミングなど）

## 3. 成功指標（反応の測り方）

計測用スクリプト（JS）はページに**入れない**（柱A と矛盾するため）。外部から見える数字だけで判断する。

| 指標 | 取得元 | 目標（公開から1か月） |
| :--- | :--- | :--- |
| Qiita 記事のいいね | Qiita | 10 以上 |
| Qiita 記事のストック | Qiita | 10 以上 |
| Qiita 記事の閲覧数 | Qiita（投稿者のみ閲覧可） | 前作記事の同期間の閲覧数を上回る |
| Zenn 記事のいいね | Zenn | 10 以上 |
| サイトへのアクセス（参考値） | Cloudflare ダッシュボードのドメイン Analytics（サーバー側集計） | 目標値は置かない。公開前1か月との比較を記録する |

* 主指標は Qiita / Zenn の数字（いいね・ストック・閲覧数）。Cloudflare の数字は他ツールやボットのアクセスが混ざるため、参考値とする
* 基準：前作（Mask & Unmask）の Qiita 記事は、2026-08-16 投稿でいいね 1
* GitHub のスター数・Issue 数は参考値として記録するだけで、目標にはしない
* Cloudflare 側でパス別（`/snap-redact/`）の集計ができない場合は、ドメイン全体の数字で比べる

## 4. システム前提・アーキテクチャ

| 項目 | 内容 |
| :--- | :--- |
| 構成 | 完全フロントエンド（Vite + React + TypeScript + Tailwind CSS）。既存2作にそろえる |
| 配信 | Cloudflare Pages。サブパス `/snap-redact/` で配信（Vite の `base` 設定） |
| サーバー・DB | なし（ユーザー登録・ログインなし） |
| 主要 Web API | Canvas API、Clipboard API（読み込みは `paste` イベント、書き込みは `navigator.clipboard.write`） |
| データ保持 | メモリ上のみ。localStorage / sessionStorage / IndexedDB にも**画像を保存しない**。リロード・タブを閉じると消える |
| ブランド | `digi-garden/brand-assets` のロゴ・favicon・共通ヘッダー／フッター・共通規約を使う。**ビルド時に同梱し、実行時に外部から読み込まない**（CSP と整合させる） |

## 5. 機能要件（MVP）

### 5.1 画像入力
| ID | 要件 |
| :--- | :--- |
| IN-1 | 画面上のどこでも `Ctrl+V` / `Cmd+V` でクリップボードの画像を読み込み、Canvas に原寸で描画する。クリップボードに複数のデータ型（`text/html` と `image/png` など）がある場合は `image/*` を優先して取り出す |
| IN-2 | 画像ファイルのドラッグ＆ドロップ、およびファイル選択で読み込める。ドロップ領域の外に落としてもブラウザが画像を開いてページを離れないよう、画面全体で `dragover` / `drop` の既定動作を止める |
| IN-3 | 対応形式は PNG / JPEG / WebP / GIF。**GIF は最初のフレームだけ**を扱う |
| IN-4 | 画像型のデータが1つもない、または読み込めない形式だった場合はトーストで知らせる |
| IN-5 | 画像を表示中に新しい画像が来たら差し替える（編集履歴も破棄）。ただし、**最後のコピー／ダウンロード以降に操作が1件以上ある場合**だけ「編集内容が破棄されます」と確認する（コピー後に次のスクショを貼る流れは止めない） |
| IN-6 | 画像未読み込み時は、Canvas 領域に「Ctrl+V でスクショを貼り付け、またはドロップ」と表示する |
| IN-7 | 画像サイズに上限を設ける。上限を超える画像、または Canvas の作成・書き出しに失敗した場合は、読み込まずにトーストで知らせる。上限値は対応ブラウザの実機で確認して決める（目安：長辺 16,384px） |

### 5.2 マスキング
| ID | 要件 |
| :--- | :--- |
| ED-1 | マウスのドラッグで矩形を指定する。ドラッグ中は選択枠を表示し、離したときに確定する |
| ED-2 | 黒塗りモード（**初期値**）：矩形を不透明な `#000000` で塗る |
| ED-3 | モザイクモード：矩形をピクセル化する。ブロックは大きめにする（画像の短辺の約2%、最低 16px） |
| ED-4 | モザイクを選んでいる間は「文字には黒塗りを推奨（モザイクは復元されうる）」と表示する |
| ED-5 | 表示座標から原寸座標へ変換したあと、矩形を**外側に向けて整数化する**（始点は切り捨て、終点は切り上げ）。縮小表示中でも、ユーザーが覆った範囲より狭くならず、端のアンチエイリアスで元の画素が透けないようにする。ドラッグ中の選択枠も、整数化した範囲で表示する |
| ED-6 | 極小の矩形（幅・高さとも 3px 未満）は無視する。ドラッグ中に `Esc` でキャンセルできる |
| ED-7 | Undo：`Ctrl+Z` / `Cmd+Z` と「↩ 元に戻す」ボタンで、直前の操作を1件ずつ取り消す |
| ED-8 | 「🗑️ クリア」：画像と編集履歴を破棄し、初期画面に戻す |
| ED-9 | 履歴は「元画像＋操作の一覧」で持ち、Undo のたびに元画像から描き直す（操作ごとに画像を丸ごと保存しない） |

### 5.3 出力
| ID | 要件 |
| :--- | :--- |
| OUT-1 | 「📋 画像をコピー」ボタンで、編集済み画像を PNG でクリップボードに書き込む。PC 版 Safari でもコピーできること（ユーザー操作の判定が切れない書き方にする） |
| OUT-2 | 画像を読み込み済みで、テキストを選択していないときは `Ctrl+C` / `Cmd+C` でも OUT-1 と同じ動作をする。画像がないときは何もしない |
| OUT-3 | 「💾 ダウンロード」ボタンで `redacted_image.png` として保存する |
| OUT-4 | 出力は常に PNG。元画像の EXIF などのメタデータは出力に含まれない（Canvas から書き出すため） |
| OUT-5 | コピー成功・失敗をトーストで知らせる。失敗した場合はダウンロードを案内する |

### 5.4 画面・表示
| ID | 要件 |
| :--- | :--- |
| UI-1 | ダークモード固定（Zinc / Slate 系）、アクセントカラー `#10B981` |
| UI-2 | ヘッダーに「🛡️ 外部通信ブロック中（CSP）」のバッジを置く。動的に監視しているように見える表現（件数・「0」など）は使わない。クリックすると、CSP の内容と DevTools での確認手順を表示する |
| UI-3 | ツールバー：黒塗り／モザイク切り替え、元に戻す、クリア |
| UI-4 | Canvas 領域を最大化する。大きい画像は表示だけ縮小し、処理と出力は原寸で行う |
| UI-5 | フッター：Mask & Unmask への導線、GitHub リンク、免責文「隠し漏れの最終確認は利用者が行ってください」 |
| UI-6 | スマホでは「PC 向けツールです。スマホはファイル選択のみ対応」と表示する |

### 5.5 画面レイアウト（1画面完結）
```text
+-----------------------------------------------------------------------+
|  ◯ CircleNote / Snap-Redact              [🛡️ 外部通信ブロック中（CSP）]   |
+-----------------------------------------------------------------------+
|  [ ⬛ 黒塗り ] [ 🏁 モザイク ] | [ ↩ 元に戻す ] | [ 🗑️ クリア ]        |
|  （モザイク選択時）⚠ 文字には黒塗りを推奨（モザイクは復元されうる）     |
+-----------------------------------------------------------------------+
|                                                                       |
|                       ( HTML5 Canvas 領域 )                           |
|        未読み込み時：「Ctrl+V でスクショを貼り付け、またはドロップ」    |
|                                                                       |
+-----------------------------------------------------------------------+
|  [ 📋 画像をコピー（Ctrl+C） ]                    [ 💾 ダウンロード ]  |
+-----------------------------------------------------------------------+
|  テキストの機密隠しは [Mask & Unmask] ／ GitHub ／ 免責文              |
+-----------------------------------------------------------------------+
```

## 6. 非機能要件

### 6.1 セキュリティ・プライバシー（最重要）
* 画像データを外部に送る処理を一切書かない
* `public/_headers` で CSP を設定する。方針は Context-Packer と同じで、最低限次を含む
  * `default-src 'self'`、`connect-src 'none'`、`img-src 'self' blob: data:`、`object-src 'none'`、`base-uri 'self'`、`form-action 'none'`、`frame-ancestors 'none'`
* サードパーティのスクリプト・フォント・アナリティクスを読み込まない
* 画像をストレージ（localStorage / sessionStorage / IndexedDB / Cache）に保存しない
* リポジトリは最初から Public のため、秘密情報の混入を次の2段で防ぐ
  * GitHub の Secret scanning と push protection を有効にする（push の時点でブロック）
  * CI で `gitleaks` を実行する
* リポジトリの設定
  * `main` にルールセットを設定する：直接 push の禁止、PR 必須、CI 成功を必須にする
  * マージ方法は Squash and merge のみ許可する。マージ後はブランチを自動で削除する
  * CodeQL（JavaScript/TypeScript）を有効にする

### 6.2 性能
* 一般的なスクショ（〜4K）で、読み込み・1回の黒塗り・コピーがそれぞれ 0.1 秒程度で終わることを目安とする
* 4K 画像で操作 20 件（モザイクを含む）の状態から Undo しても、体感で引っかからないこと

### 6.3 対応ブラウザ
* PC 版の Chrome / Edge / Safari / Firefox の最新版
* スマホは表示とファイル選択のみ（貼り付け・コピーは動作保証しない）

### 6.4 品質
* CI（GitHub Actions）：型チェック、lint、単体テスト、ビルド、gitleaks がすべて成功すること（ルールセットでマージ条件にする）
* 座標変換・矩形の正規化・履歴管理は単体テストで確認する

---

## 7. スコープ外（MVP ではやらない）
* OCR による自動検出（v2 以降）
* 矩形以外の範囲指定（自由形状・円）、ぼかし、白塗り
* 確定済み矩形の移動・リサイズ
* 注釈（矢印・文字）、トリミング
* 複数画像の一括処理
* スマホでの貼り付け・コピー操作

---

## 8. 進め方
1. 要件定義（本書）を確定する
2. 基本設計：画面、状態遷移、モジュール構成、CSP、テスト観点の資料を作る
3. 実装をフェーズに分ける
4. フェーズごとに「実装 → 自動テスト → レビュー」を繰り返す。重大な指摘が 0 件になったら次のフェーズへ進む
5. PR は Squash and merge。公開した版にはタグを付ける（初回公開は `v0.1.0`）

## 9. 記事の方針（公開と同時に投稿）
* 前作の記事で「CSP でブラウザ内完結を担保する」はすでに書いたため、今回の主軸はスクショ固有の話にする
  * 黒塗りの端から元の画素が漏れる問題（整数ピクセルにそろえる理由）
  * モザイクが復元されうる理由と、文字には黒塗りを勧める理由
  * `Ctrl+C` でコピーまで完結させる実装と、Safari のクリップボードの癖
  * EXIF（位置情報など）が出力から消える仕組み
* 送信しないことの確認手順（DevTools）を記事内に載せ、リポジトリへのリンクを置く
* タイトルは「作った」報告ではなく、読者の困りごとから入る形にする
